pb-dic-converter Architecture

Two kinds of source become a common TSV, then XDXF, then a dictionary for the reader: a PocketBook .dic or StarDict files for KOReader. Every tool is a single Java file run from source, sharing one small library in java/shared. Configs (.properties with def variables, overridable with --def) feed every tool, and the chain-* scripts run several steps from one config.

Applies to every converter: kaikki-2-tab, stardict-2-tab, tab-2-xdxf, xdxf-2-pbdic and xdxf-2-stardict. The last replaces its stardict.* files only once all of them are built, .ifo last, and refuses at the start if one of them is read-only.

Merging duplicate headwords

Both XDXF tools merge the same way, driven by MergeMode (-m). Its table gives each mode a word key (ALWAYS: lowercase, so case variants are one headword), whether different definitions are joined, and which spelling names the joined entry. ALWAYS picks the most common spelling with TextHelper.wordKind: COMMON, then NAME, then ACRONYM, then fewer capitals.
